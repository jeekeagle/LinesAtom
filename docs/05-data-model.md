# 数据模型

## 概念条目

| 字段 | 说明 |
| --- | --- |
| 编号 | 全库递增，`c01` 起 |
| 名称 | 讲稿中真实出现的术语 |
| 定义 | 一句话，不超过四十字 |
| 上位类 | 指向父概念编号，无父类填根 |
| 同层差异 | 与最相近概念的区别点 |
| 易混项 | 常见误解，一到三条 |
| 锚点位置 | 首次出现的讲稿块编号 |
| 回指位置 | 后续出现位置的块编号列表 |
| 关联介质 | 卡片编号、案例编号、问答编号 |

## 讲稿块

块编号、顺序号、正文、标签（六类之一）、挂载指针（零到多个）。

## 挂载指针

所属块编号、介质类型、目标编号、触发方式（预挂或入口）、状态（已确认 / 建议）。

指针只存编号，不存内容。内容随概念条目与介质内容独立维护，可跨课复用。

## 介质内容

`media` 分为 `cases`、`qas`、`cheatsheets`、`slides`、`maps` 五组，与 `concepts` 并列存在。概念卡的内容就是概念条目本身，不重复存储。

## 挂载建议

`project.suggestions` 是逐行建议层：块编号、介质类型、目标、理由、置信度、状态（待确认 / 已确认 / 已拒绝 / 已修改）、来源（引擎 / 模型）。

建议是给人看的提案，不是挂载事实。确认后写入挂载指针，拒绝后保留痕迹。

## 标签与挂载规则

| 标签 | 判定（删掉这一块会发生什么） | 挂载 |
| --- | --- | --- |
| 核心概念 | 后文某个术语失去来源 | 概念卡 |
| 理解性例子 | 概念仍成立，理解难度上升 | 案例 |
| 设问互动 | 该段由互动转为陈述 | 问答 |
| 结论收束 | 该段没有落点 | 速查表 |
| 全局定位 | 听众失去位置判断 | 课件页或章节导图 |
| 过渡衔接 | 前后段出现跳跃 | 不挂载，仅作导航 |

回指处理：同一概念后续出现处只标回指，不重复挂载；回指位置保留跳转指向锚点。
